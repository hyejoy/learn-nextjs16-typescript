# children props로 서버 컴포넌트 결과 표시하기

## 복습: 안 되는 것

클라이언트 컴포넌트에서 서버 컴포넌트를 **직접 import하여 렌더링하는 것은 불가능**합니다.

```tsx
"use client";
import DataFetch from "./DataFetch"; // 서버 컴포넌트

export default function Page() {
  return <DataFetch />; // ❌ 에러 발생
}
```

## 그런데 가능한 방법이 있다: children props

렌더링의 **결과만 표시**하는 목적이라면 `children` props를 이용해 우회할 수 있습니다.

### 예시 구조

**1. ClientWrapper.tsx (클라이언트 컴포넌트)**

```tsx
"use client";

export default function ClientWrapper({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return <div>{children}</div>;
}
```

- `children`을 받아서 그대로 렌더링만 하는 역할

**2. Page 컴포넌트 (서버 컴포넌트, `use client` 없음)**

```tsx
export default function Page() {
  return (
    <ClientWrapper>
      <DataFetch /> {/* 서버 컴포넌트 */}
    </ClientWrapper>
  );
}
```

이렇게 작성하면 `ClientWrapper`가 클라이언트 컴포넌트임에도 불구하고, 그 안에 서버 컴포넌트인 `DataFetch`가 정상적으로 렌더링됩니다.

### 왜 되는가

- `DataFetch`(서버 컴포넌트)를 **import하고 렌더링하는 주체는 Page 컴포넌트**(서버 컴포넌트)
- `ClientWrapper`는 이미 렌더링이 끝난 결과물을 `children` props로 **전달받아 표시만** 함
- 즉, `ClientWrapper`가 서버 컴포넌트를 렌더링한 것이 아니라, **다른 서버 컴포넌트(Page)가 렌더링한 결과를 전달받아 보여주는 것**

## 실행 컨텍스트(execution context)로 이해하기

### 일반적인 import 렌더링 구조 (A → B → C)

```
A 컴포넌트
 └─ import & render B
      └─ import & render C
```

- A, B, C는 **모두 같은 실행 컨텍스트를 공유**
- A → B, B → C로 props 전달 모두 가능

### children 전달 구조 (A가 B, C를 모두 import하는 경우)

```
A 컴포넌트
 ├─ import & render B (ClientWrapper)
 └─ import & render C (DataFetch) → B의 children으로 전달
```

- A와 B는 같은 실행 컨텍스트 공유
- A와 C도 같은 실행 컨텍스트 공유
- **B와 C는 실행 컨텍스트를 공유하지 않음**
  - C를 import하고 렌더링하는 주체가 A이지 B가 아니기 때문
  - B는 A가 실행을 마친 결과물을 props(children)로 전달받아 표시만 함

### props 전달 가능 여부 정리

| 관계  | 가능 여부 |
| ----- | --------- |
| A → B | ✅ 가능   |
| A → C | ✅ 가능   |
| B → C | ❌ 불가능 |

## 이번 예제에 적용하면

- **Page(A)** → **ClientWrapper(B)**: 같은 실행 컨텍스트 (import & render)
- **Page(A)** → **DataFetch(C)**: 같은 실행 컨텍스트 (import & render, children으로 전달)
- **ClientWrapper(B)** ↔ **DataFetch(C)**: 실행 컨텍스트 공유 안 함

따라서:

- Page → DataFetch로 props 전달 ✅ 가능
- ClientWrapper → DataFetch로 props 전달 ❌ 불가능

## 결론

- `children` props를 사용하면 클라이언트 컴포넌트 안에서도 서버 컴포넌트의 **렌더링 결과**를 표시할 수 있음
- 단, 엄밀히 말하면 **클라이언트 컴포넌트가 서버 컴포넌트를 렌더링한 것이 아니라**, 다른 서버 컴포넌트가 미리 렌더링한 결과를 전달받아 표시해준 것뿐임
- 이 개념은 서버/클라이언트 컴포넌트의 **실행 시점 차이**와 **실행 컨텍스트**를 정확히 이해해야 헷갈리지 않음
