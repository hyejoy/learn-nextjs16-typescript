# error.tsx (Error Boundary)

## error.tsx란?

> **예기치 않은 런타임 오류**가 발생했을 때, 이를 처리하고 사용자에게 **대체 UI**를 표시할 수 있게 해주는 특수 파일

- `loading.tsx`가 페이지를 `Suspense`로 감싸듯, `error.tsx`는 같은 위치의 **페이지 컴포넌트를 Error Boundary 경계로 감쌈**
- `error.tsx`의 내용이 그 Error Boundary의 **fallback UI**로 사용됨
- ⚠️ **반드시 클라이언트 컴포넌트로 작성해야 함**

## 기본 사용법

```tsx
// app/page.tsx
export default function Page() {
  throw new Error("인위적인 에러 발생");
}
```

- `error.tsx`가 없으면: Next.js가 기본 제공하는 **내장 에러 오버레이**가 표시됨
- `error.tsx`가 있으면: 그 컴포넌트 내용이 대신 표시됨

```tsx
// app/error.tsx
"use client";

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <div>
      <p>에러 발생: {error.message}</p>
      <button onClick={() => reset()}>다시 시도하기</button>
    </div>
  );
}
```

### props 타입

| props   | 타입                         | 설명                                      |
| ------- | ---------------------------- | ----------------------------------------- |
| `error` | `Error & { digest: string }` | 발생한 에러 정보 (인터섹션 타입)          |
| `reset` | `() => void`                 | 에러가 발생한 라우트를 다시 호출하는 함수 |

- `error.message`로 에러 내용을 사용자에게 표시 가능
- `reset()` 함수를 버튼 클릭 등에 연결하면, **에러가 발생한 경로를 다시 렌더링** 시도

## reset() 함수 동작 확인 예제

```tsx
"use client";

// eslint-disable-next-line
const randomNumber = Math.floor(Math.random() * 3) + 1; // 1~3 랜덤

export default function Page() {
  if (randomNumber === 1) {
    throw new Error("랜덤하게 발생한 에러");
  }
  return <div>정상 렌더링</div>;
}
```

- `randomNumber`가 1일 때 에러 발생 → `error.tsx`가 표시됨
- "다시 시도하기" 버튼(= `reset()`) 클릭 → 라우트를 다시 호출 → `randomNumber`를 다시 뽑음 → 1이 아니면 정상 렌더링으로 복구

### 한계

- **에러가 발생한 컴포넌트는 반드시 클라이언트 컴포넌트여야 함**
- `reset()`을 눌러도 **근본적으로 복구되지 않는 성격의 에러**라면 계속 같은 에러가 재발생함 (재시도만 가능하지 무조건 해결을 보장하진 않음)

## 세그먼트 폴더별 error.tsx

`error.tsx`도 라우트 그룹/세그먼트 폴더에 각각 추가할 수 있습니다.

```
app/
 ├── error.tsx           (전역 에러 처리)
 └── about/
      ├── layout.tsx
      ├── error.tsx        (about 전용 에러 처리)
      └── page.tsx          (랜덤하게 에러 발생)
```

### 동작 원리

- `about/page.tsx`에서 에러 발생 → **`about/error.tsx`**가 fallback UI로 표시됨 (`app/error.tsx`가 아님)
- 즉, 각 세그먼트의 `error.tsx`는 **자신과 가장 가까운 페이지 컴포넌트**를 감쌈

## ⚠️ 핵심 주의사항: layout.tsx는 감싸지 못함

`error.tsx`의 Error Boundary는 **같은 위치의 페이지 컴포넌트만** 감쌉니다. **같은 폴더의 `layout.tsx`는 감싸지 못합니다.**

```
about/
 ├── layout.tsx   ← about/error.tsx가 감싸지 못함
 ├── error.tsx
 └── page.tsx     ← about/error.tsx가 감쌈
```

- `about/layout.tsx`에서 에러가 발생하면, `about/error.tsx`는 처리하지 못함
- 대신 **상위(`app/error.tsx`)**가 그 에러를 처리함 (about의 layout까지 포함해서 감싸는 것은 app 레벨의 error.tsx이기 때문)

### 확인

```tsx
// app/about/layout.tsx
export default function AboutLayout({ children }) {
  throw new Error("About Layout 에러");
  return <div>{children}</div>;
}
```

- 이 경우 `about/error.tsx`가 아니라 **`app/error.tsx`**가 렌더링됨

## Error Boundary 범위 정리

| 에러 발생 위치                   | 처리하는 error.tsx                                                                 |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `about/page.tsx`                 | `about/error.tsx` (가장 가까운 error.tsx)                                          |
| `about/layout.tsx`               | `app/error.tsx` (상위 error.tsx) — about의 error.tsx는 페이지만 감싸므로 영향 없음 |
| `app/layout.tsx` (루트 레이아웃) | **그 어떤 error.tsx로도 처리 불가**                                                |

## 남은 문제: 루트 레이아웃의 에러

- 이 구조상 **루트 레이아웃(`app/layout.tsx`)에서 발생한 에러는 어떠한 `error.tsx`로도 처리할 수 없음**
- 루트 레이아웃의 에러를 처리하려면 **다른 특수 파일**이 필요 (다음 학습에서 다룰 예정)

## 정리

- `error.tsx`는 같은 위치의 **페이지 컴포넌트**를 Error Boundary로 감싸는 특수 파일 (**클라이언트 컴포넌트 필수**)
- `error`(에러 정보), `reset`(재시도 함수) props를 받아 사용자 친화적인 에러 UI를 구성
- **레이아웃의 에러는 처리하지 못하며**, 그 경우 상위의 `error.tsx`가 처리
- 루트 레이아웃의 에러는 어떤 `error.tsx`로도 처리 불가 → 별도의 특수 파일 필요
