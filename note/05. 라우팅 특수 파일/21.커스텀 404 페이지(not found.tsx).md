# 커스텀 404 페이지 (not-found.tsx)

## 기본 동작

- Next.js App Router는 존재하지 않는 경로로 접근하면 **자동으로 내장된 404 페이지**를 렌더링
- 별도 설정 없이도 기본 제공되지만, 프로젝트 디자인에 맞게 **커스터마이징**하고 싶을 때가 있음

## not-found.tsx 파일

> App Router에서 404 페이지를 커스터마이징할 때 사용하는 **특수 파일**

```
app/
 └── not-found.tsx
```

```tsx
// app/not-found.tsx
export default function NotFound() {
  return <div>페이지를 찾을 수 없습니다.</div>;
}
```

- `app` 폴더 바로 하위에 `not-found.tsx`를 만들면, 존재하지 않는 경로 접근 시 **내장 404 페이지 대신 이 컴포넌트가 렌더링**됨

## 하위 폴더에 not-found.tsx 추가하기

`not-found.tsx`는 App Router 최상위뿐 아니라 **라우트 세그먼트 폴더**나 **라우트 그룹 폴더** 하위에도 추가로 만들 수 있습니다. 단, **동작 방식이 다릅니다.**

### 예시 구조

```
app/
 ├── not-found.tsx          (전역 404)
 └── posts/
      ├── not-found.tsx     (posts 전용 404)
      └── [id]/
           └── page.tsx
```

### 존재하지 않는 경로로 접근할 경우

- 예: `/posts/1/comment` (정의되지 않은 경로)
- 결과: `posts` 폴더 밑에 `not-found.tsx`를 만들어도, **여전히 `app` 폴더 최상위의 `not-found.tsx`가 렌더링됨**

### ⚠️ 핵심 규칙

> 존재하지 않는 경로(매칭되는 라우트 자체가 없는 경우)에 접근했을 때는, 라우트 세그먼트/그룹 폴더에 `not-found.tsx`를 만들어도 **항상 App Router 최상위의 `not-found.tsx`가 호출됨**

즉, 하위 폴더의 `not-found.tsx`는 **URL 매칭 실패 상황에서는 사용되지 않습니다.**

## 하위 not-found.tsx를 실제로 사용하는 방법: notFound() 함수

하위 폴더의 `not-found.tsx`를 활용하려면, **컴포넌트 코드 내부에서 `notFound()` 함수를 직접 호출**해야 합니다.

```tsx
// app/posts/[id]/page.tsx
import { notFound } from "next/navigation";

export default async function PostDetail({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  if (id === "10") {
    notFound(); // 없는 게시글이라고 가정
  }

  return <div>Post ID: {id}</div>;
}
```

- `notFound` 함수는 **`next/navigation`** 패키지에서 import
- 개발자가 정의한 조건(예: 존재하지 않는 게시글 id)에서 직접 호출

### 동작 방식

- `/posts/1`, `/posts/2` → 정상적으로 페이지 렌더링
- `/posts/10` → `notFound()` 호출 → **404 페이지 렌더링**

이때 렌더링되는 `not-found.tsx`는:

> **`notFound()` 함수가 호출된 파일의 위치를 기준으로, 가장 가까운 곳에 있는 `not-found.tsx`**

- `posts/[id]/page.tsx`에서 `notFound()`를 호출했으므로, `app/posts/not-found.tsx`가 `app/not-found.tsx`보다 **우선적으로 렌더링됨**

## 정리

| 상황                                            | 렌더링되는 not-found.tsx                      |
| ----------------------------------------------- | --------------------------------------------- |
| 존재하지 않는 경로(URL 매칭 실패)로 접근        | 항상 **App Router 최상위**의 `not-found.tsx`  |
| 컴포넌트 내부에서 `notFound()` 함수를 직접 호출 | 호출 위치에서 **가장 가까운** `not-found.tsx` |

- 라우트 매칭 자체가 실패하는 경우와, 코드 로직상 "없는 데이터"로 판단해 404를 띄우는 경우는 **동작 방식이 다름**
- 후자의 경우에만 라우트 세그먼트/그룹 폴더에 만든 커스텀 `not-found.tsx`를 활용할 수 있음
