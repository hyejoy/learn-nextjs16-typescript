# loading.tsx (Suspense 경계와 로딩 UI)

## loading.tsx란?

> 같은 폴더 내에 있는 **페이지 컴포넌트를 Suspense 경계로 감싸는 역할**을 수행하는 특수 파일

- 페이지가 렌더링되기 전에 보여줄 **대체(fallback) UI**를 정의
- `loading.tsx` 파일을 만들면, Next.js가 자동으로 같은 위치의 `page.tsx`를 **`<Suspense>`로 감싸고**, `loading.tsx`의 내용을 **fallback UI**로 사용

## 지연(delay)이 있을 때의 차이

### loading.tsx가 없는 경우

```tsx
// app/page.tsx
export default async function Page() {
  await new Promise((resolve) => setTimeout(resolve, 3000)); // 3초 지연
  return <div>Home Page</div>;
}
```

- 루트 경로 접근 시 **3초 동안 화면에 아무것도 표시되지 않음** (완전히 차단된 것처럼 보임)

### loading.tsx가 있는 경우

```tsx
// app/loading.tsx
export default function Loading() {
  return <div>Loading...</div>;
}
```

- 같은 3초 지연이 있어도, 지연되는 동안 **`loading.tsx`의 내용이 먼저 표시됨**
- 사용자에게 화면이 멈춘 느낌을 주지 않고, **더 부드럽고 직관적인 로딩 경험** 제공

## ⚠️ 핵심 주의사항: 루트 레이아웃의 지연은 처리하지 못함

`loading.tsx`가 Suspense 경계로 감싸는 대상은 **오직 페이지 컴포넌트(`page.tsx`)뿐**입니다. **레이아웃(`layout.tsx`)에서 발생하는 지연은 처리하지 못합니다.**

```tsx
// app/layout.tsx
export default async function RootLayout({ children }) {
  await new Promise((resolve) => setTimeout(resolve, 3000)); // 레이아웃에서 지연
  return (
    <html>
      <body>{children}</body>
    </html>
  );
}
```

- 이 경우 `loading.tsx`가 있어도 **3초 동안 아무것도 보이지 않음** (레이아웃은 Suspense로 감싸지지 않기 때문)

### 해결책: 지연 코드를 별도 컴포넌트로 분리 + 직접 Suspense 사용

```tsx
// components/Delay.tsx
export default async function Delay() {
  await new Promise((resolve) => setTimeout(resolve, 3000));
  return <div>지연된 콘텐츠</div>;
}
```

```tsx
// app/layout.tsx
import { Suspense } from "react";
import Delay from "@/components/Delay";

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Suspense fallback={<div>루트 레이아웃 로딩...</div>}>
          <Delay />
        </Suspense>
        {children}
      </body>
    </html>
  );
}
```

- 레이아웃에서 지연이 예상되는 코드는 **별도 컴포넌트로 분리**하고, **직접 `<Suspense>`로 감싸서** 처리해야 함
- `loading.tsx`는 페이지 컴포넌트 전용이므로, 레이아웃의 지연 문제는 이렇게 별도로 대응 필요

## 세그먼트 폴더별 loading.tsx 중첩

`loading.tsx`는 라우트 그룹/세그먼트 폴더에도 각각 추가할 수 있습니다.

```
app/
 ├── layout.tsx
 ├── loading.tsx       (전역 로딩)
 └── about/
      ├── layout.tsx
      ├── loading.tsx    (about 전용 로딩)
      └── page.tsx        (지연 발생)
```

### 동작 원리

- `about` 경로의 페이지 컴포넌트는 **자신과 가장 가까운 `loading.tsx`**(즉 `about/loading.tsx`)에 의해 Suspense로 감싸짐
- 상위(`app/loading.tsx`)도 별도의 Suspense 경계를 형성하므로, **Suspense가 중첩되는 구조**

### 중첩 렌더링 구조 (layout까지 포함한 경우)

```
Root Layout
 └── Root Loading(Suspense)
      └── About Layout
           └── About Loading(Suspense)
                └── About Page
```

- `about/page.tsx`에서 지연 발생 → **`about/loading.tsx`**가 대체 UI로 표시
- `about/layout.tsx`에서 지연 발생 → `about/loading.tsx`는 **페이지만 감싸므로 영향 없음** → 대신 **상위(`app/loading.tsx`)**가 대체 UI로 표시됨

## 정리

| 지연 발생 위치                   | 대체 UI를 제공하는 파일                                                                  |
| -------------------------------- | ---------------------------------------------------------------------------------------- |
| `about/page.tsx`                 | `about/loading.tsx` (가장 가까운 loading.tsx)                                            |
| `about/layout.tsx`               | `app/loading.tsx` (상위 loading.tsx) — about의 loading.tsx는 페이지만 감싸므로 영향 없음 |
| `app/layout.tsx` (루트 레이아웃) | 처리 불가 — 별도 컴포넌트 분리 + 직접 `<Suspense>` 필요                                  |

- `loading.tsx`는 **같은 위치의 `page.tsx`만** Suspense 경계로 감쌈
- 레이아웃(`layout.tsx`)의 지연은 `loading.tsx`가 처리하지 못하므로, 지연 가능성이 있는 코드는 **별도 컴포넌트 + 직접 `<Suspense>`** 로 분리해서 다뤄야 함
- 세그먼트 폴더별로 `loading.tsx`를 추가하면, 각 경로에 맞는 세분화된 로딩 UI를 구성할 수 있음
- 이 원리를 이해하면 서버 컴포넌트의 비동기 처리로 인한 렌더링 지연을 **사용자 친화적인 로딩 화면**으로 자연스럽게 대체할 수 있음
