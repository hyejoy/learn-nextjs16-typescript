# global-not-found.tsx

## not-found.tsx의 숨겨진 특징: 루트 레이아웃을 거침

앞서 배운 `not-found.tsx`는 없는 경로에 접근했을 때 렌더링되지만, **단독으로 렌더링되는 것이 아니라 루트 레이아웃의 `children` 자리에 렌더링**됩니다.

### 확인 방법

```tsx
// app/layout.tsx
export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html>
      <body>
        <header>공통 헤더</header>
        {children}
        <footer>공통 푸터</footer>
      </body>
    </html>
  );
}
```

- 없는 경로(예: `/about`)로 접근해서 `not-found.tsx`가 렌더링되어도, **헤더/푸터는 그대로 함께 렌더링됨**
- 즉, `not-found.tsx`는 루트 레이아웃의 `children`으로서 나타나는 것

## 문제: 완전히 독립적인 404 페이지가 필요할 때

경우에 따라 기존 레이아웃(헤더/푸터 등)을 완전히 무시하고, **전혀 다른 UI 구성으로 독립적인 404 페이지**를 만들고 싶을 수 있습니다.

- 예: 메인 사이트는 헤더/푸터 포함, 404 페이지는 로고만 간단히 표시

이럴 때 사용하는 것이 **`global-not-found.tsx`** 파일입니다.

## global-not-found.tsx란?

> **루트 레이아웃을 거치지 않고 완전히 독립적으로 렌더링되는** 404 페이지를 만들 때 사용하는 특수 파일

### 현재 상태: 실험적 기능

이 영상 촬영 시점 기준으로 아직 **실험적(experimental) 기능**이므로 별도 설정이 필요합니다.

```ts
// next.config.ts
const nextConfig = {
  experimental: {
    globalNotFound: true,
  },
};

export default nextConfig;
```

### 설정 후 변화

`experimental.globalNotFound`를 `true`로 설정하는 순간:

- **루트 경로의 `not-found.tsx` 파일은 더 이상 없는 경로에 자동으로 매칭되지 않음**
- 대신 없는 경로에 접근하면 Next.js 내장 404 페이지가 잠시 보이며, **`global-not-found.tsx`가 이 역할을 담당**해야 함

## global-not-found.tsx 작성 시 주의점

`global-not-found.tsx`는 **루트 레이아웃을 거치지 않고 렌더링**되므로, **반드시 독립적으로 `<html>`, `<body>` 태그를 포함**해야 합니다.

```tsx
// app/global-not-found.tsx
export default function GlobalNotFound() {
  return (
    <html>
      <body>
        <div>페이지를 찾을 수 없습니다.</div>
      </body>
    </html>
  );
}
```

- 이렇게 작성하면, 공통 헤더/푸터 없이 **완전히 독립된 형태**로 404 페이지가 렌더링됨

## global-not-found.tsx 사용 중에도 not-found.tsx는 유효

`globalNotFound` 옵션을 `true`로 설정했더라도, 라우트 그룹/세그먼트 폴더에 **`not-found.tsx`를 추가하는 것은 여전히 가능**합니다.

- 단, 이전 강의에서 배운 것처럼 이 하위 `not-found.tsx`는 **URL 매칭 실패 상황에는 사용되지 않고**, **`notFound()` 함수를 직접 호출할 때만** 사용됨

```tsx
// app/posts/[id]/page.tsx
import { notFound } from "next/navigation";

export default async function PostDetail({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  if (id === "10") {
    notFound(); // posts 폴더의 not-found.tsx가 렌더링됨
  }

  return <div>Post ID: {id}</div>;
}
```

## not-found.tsx vs global-not-found.tsx 비교

| 구분                    | not-found.tsx                         | global-not-found.tsx                                                             |
| ----------------------- | ------------------------------------- | -------------------------------------------------------------------------------- |
| 루트 레이아웃           | **거침** (children으로 렌더링)        | **거치지 않음** (완전 독립)                                                      |
| html/body 태그          | 불필요 (루트 레이아웃이 제공)         | **필수로 직접 포함**                                                             |
| 활성화 조건             | 기본 제공                             | `next.config.ts`에서 `experimental.globalNotFound: true` 설정 필요 (실험적 기능) |
| 없는 경로 매칭          | 옵션 켜기 전엔 이 파일이 담당         | 옵션 켠 후엔 이 파일이 담당                                                      |
| 하위 폴더 not-found.tsx | 그대로 사용 가능 (notFound() 호출 시) | 그대로 사용 가능 (notFound() 호출 시)                                            |

## 정리

- **`not-found.tsx`**: 루트 레이아웃을 포함한 상태로 404 페이지를 렌더링할 때 사용
- **`global-not-found.tsx`**: 루트 레이아웃을 완전히 거치지 않고 독립적으로 404 페이지를 렌더링할 때 사용 (실험적 기능, 별도 설정 필요, html/body 직접 포함 필수)
- `global-not-found.tsx`를 사용하더라도 라우트 폴더/그룹별 `not-found.tsx`는 `notFound()` 함수 호출을 통해 그대로 활용 가능
