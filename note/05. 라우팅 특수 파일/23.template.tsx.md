# template.tsx (layout.tsx와의 차이)

## layout.tsx와 template.tsx의 공통점

- 둘 다 **페이지나 하위 라우트를 감싸는 래퍼(wrapper)** 역할을 함
- 실제로 `layout.tsx` 파일 이름을 `template.tsx`로 바꿔도 정상적으로 페이지가 렌더링됨

## 결정적인 차이: remount 여부

| 구분           | 라우트 전환 시 동작                                        |
| -------------- | ---------------------------------------------------------- |
| `layout.tsx`   | 한 번 마운트되면 **다시 언마운트/마운트되지 않고 값 유지** |
| `template.tsx` | 경로가 변경될 때마다 **매번 unmount → mount(remount)**     |

### 원리

- Next.js는 `template.tsx`에 암묵적으로 **`key`** 속성을 부여하며, 이 `key`는 **경로 값**을 그대로 가져옴
- `key` 값이 바뀌면 React는 컴포넌트를 **다른 컴포넌트로 취급**하여 언마운트 후 다시 마운트함
- 따라서 라우트가 전환될 때마다 `template.tsx`는 매번 새로 mount됨

## 실험으로 확인하기

```tsx
// components/Search.tsx
"use client";

import { useEffect } from "react";

export default function Search() {
  useEffect(() => {
    console.log("Search 컴포넌트 마운트");
  }, []);

  return <div>Search</div>;
}
```

### layout.tsx에서 Search 렌더링

- `/` → `/about`으로 이동해도 **콘솔 메시지가 다시 출력되지 않음** (리마운트 없음)

### template.tsx로 바꿔서 Search 렌더링

- `/` → `/about`으로 이동하면 **콘솔 메시지가 다시 출력됨** (리마운트 발생)

## ⚠️ template를 단독으로 사용하면 안 되는 이유

`template.tsx`만 단독으로 사용하면:

- 라우트 전환 시마다 `key` 값이 바뀌면서 **애플리케이션 전체가 리마운트/언마운트**되는 것과 같은 효과 발생
- 결과적으로 **페이지 전환마다 전체 리소스를 다시 다운로드**하게 됨
- 추가로 `template.tsx`는 **메타데이터 관련 설정을 적용할 수 없음**

→ 따라서 **`template.tsx`는 `layout.tsx`와 함께 사용하는 것을 권장**

## 권장 사용법: 루트 레이아웃 + 템플릿

```tsx
// app/layout.tsx
export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html>
      <body>{children}</body>
    </html>
  );
}
```

```tsx
// app/template.tsx
export default function RootTemplate({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return <div>{children}</div>;
}
```

- `template.tsx`에는 `html`, `body` 태그를 넣지 않음 (루트 레이아웃이 이미 포함하고 있으므로)

### 최종 렌더링 중첩 구조

```
RootLayout
 └── RootTemplate
      └── Page
```

- `RootLayout`: 한 번 마운트되면 유지 (래퍼 역할)
- `RootTemplate`: 경로(key)가 바뀔 때마다 리마운트
- 이 구조 덕분에 **전체 화면이 새로고침되듯 깜빡이진 않으면서도(공유 레이아웃 유지)**, 내부적으로는 template가 매번 리마운트됨

## 중요한 예외: 첫 번째 세그먼트가 바뀔 때만 감지

`template.tsx`는 **첫 번째 세그먼트가 달라질 때만** 리마운트를 감지합니다.

- 예: `/about` → `/about/contact`처럼 **같은 첫 번째 세그먼트(about)** 안에서 이동하면, **루트의 `template.tsx`는 리마운트되지 않음**

### 확인

```
/about → Search 콘솔 출력됨 (최초 마운트)
/about → /about/contact 이동 → Search 콘솔 출력 안 됨 (리마운트 없음)
```

## 하위 세그먼트에서도 리마운트가 필요하다면?

해당 세그먼트 폴더에 **자체 `template.tsx`를 추가**하면 됩니다.

```
app/
 ├── layout.tsx        (Root Layout)
 ├── template.tsx       (Root Template)
 └── about/
      ├── layout.tsx     (About Layout)
      ├── template.tsx    (About Template)
      ├── page.tsx
      └── contact/
           └── page.tsx
```

- `about/template.tsx`에 `Search` 컴포넌트를 렌더링하면:
  - `/about` → `/about/contact` 이동 시 **About Template이 리마운트되면서 Search도 다시 마운트됨**

### 최종 중첩 구조

```
Root Layout
 └── Root Template
      └── About Layout
           └── About Template
                └── Page
```

## 각 파일의 리마운트 조건 정리

| 파일           | 리마운트 조건                                                           |
| -------------- | ----------------------------------------------------------------------- |
| Root Layout    | 리마운트 안 됨 (항상 유지)                                              |
| Root Template  | **첫 번째 세그먼트**가 바뀔 때만 리마운트                               |
| About Layout   | 리마운트 안 됨 (About 하위에서는 항상 유지)                             |
| About Template | About 하위 경로(예: `/about` → `/about/contact`)가 바뀔 때마다 리마운트 |

## 정리

- `template.tsx`는 `layout.tsx`와 달리 **라우트 전환 시 unmount/mount(remount)가 발생**하는 특수 파일
- 단독 사용 시 전체 리소스 재다운로드, 메타데이터 미지원 문제가 있으므로 **루트 레이아웃과 함께 사용 권장**
- **최상위 `template.tsx`는 첫 번째 세그먼트가 바뀔 때만** 리마운트를 감지
- 하위 세그먼트 이동 시에도 리마운트가 필요하다면, 해당 세그먼트 폴더에 **자체 `template.tsx`를 추가**하면 됨
- 라우트 전환 시마다 컴포넌트를 초기화(리마운트)해야 하는 상황에서 `template.tsx`를 유용하게 활용할 수 있음
