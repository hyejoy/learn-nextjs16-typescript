# 동적 라우트 (Dynamic Routes)

## 문제 상황

`/post/1`처럼 두 번째 세그먼트가 고정된 값이라면 지금까지 배운 **중첩 라우트** 방식으로 충분합니다.

```
app/
 └── post/
      └── 1/
           └── page.tsx
```

하지만 블로그 게시글처럼 `/post/1`, `/post/2`, `/post/3`... 처럼 **두 번째 세그먼트가 계속 동적으로 바뀌는 경우**, 매번 폴더를 수동으로 추가하는 것은 비효율적입니다.

## 동적 라우트란?

> 동적으로 변경되는 세그먼트에 해당하는 폴더를 **대괄호 `[ ]`로 감싸서 정의**하는 방식

```
app/
 └── post/
      └── [id]/
           └── page.tsx
```

- 대괄호 안의 식별자(`id`)는 **동적으로 변경되는 값이 의미하는 바**를 적어줌 (예: 게시글 id)
- `[id]` 폴더는 **동적 세그먼트 폴더**가 되며, 어떤 값이 오더라도 매칭됨
  - `/post/1`, `/post/2`, `/post/100` 등 모두 이 폴더 하나로 대응 가능

## 컴포넌트에서 동적 세그먼트 값 가져오기

동적 세그먼트로 지정한 값을 컴포넌트 내부에서 활용하는 경우가 많습니다. 서버 컴포넌트와 클라이언트 컴포넌트에서 값을 가져오는 방법이 다릅니다.

### 서버 컴포넌트: params props

```tsx
// app/post/[id]/page.tsx
export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  return <div>Post ID: {id}</div>;
}
```

- `params`는 페이지 컴포넌트에 **기본적으로 전달되는 props**
- 타입은 `Promise` 형태이며, 동적 세그먼트 폴더의 식별자를 키로 사용 (`id: string`)
- `await params`로 값을 꺼낸 뒤 구조 분해 할당으로 사용
- `/post/1` 접근 → `id`는 `"1"`, `/post/2` 접근 → `id`는 `"2"`

### 클라이언트 컴포넌트: useParams 훅

```tsx
"use client";

import { useParams } from "next/navigation";

export default function PostDetailPage() {
  const { id } = useParams<{ id: string }>();

  return <div>Post ID: {id}</div>;
}
```

- `"use client"` 지시어로 클라이언트 컴포넌트로 전환
- `useParams()` 훅을 사용해 동적 세그먼트 폴더의 식별자(`id`)를 그대로 받아올 수 있음

## 서버 vs 클라이언트 비교

| 구분                | 사용 방식                                                       |
| ------------------- | --------------------------------------------------------------- |
| 서버 컴포넌트       | `async` 함수 + `params` props (`Promise` 타입) → `await params` |
| 클라이언트 컴포넌트 | `"use client"` + `useParams()` 훅                               |

## 정리

- 동적 라우트는 폴더명을 **대괄호 `[식별자]`**로 감싸서 정의
- URL에 전달되는 값에 따라 **유연하게 페이지를 생성**할 수 있음
- 게시글 상세 페이지, 사용자 프로필 페이지 등 실무에서 매우 자주 사용되는 패턴
