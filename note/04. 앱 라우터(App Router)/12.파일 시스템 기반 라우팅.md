# 파일 시스템 기반 라우팅

## App Router의 라우팅 방식

- App Router는 **폴더와 파일의 구조만으로 자동으로 라우트를 정의**함 → **파일 시스템 기반 라우팅**
- 별도의 설정이나 라우트 등록 과정 없이, **폴더를 만들고 `page.tsx` 파일을 생성**하면 Next.js가 그 구조를 자동으로 인식해 경로를 만듦

## 루트 경로의 최소 구성

처음 프로젝트를 생성하면 `app` 폴더 하위에 `layout.tsx`와 `page.tsx`가 있는 이유는, 이 두 파일이 **루트 경로에 대한 라우트를 구성하기 위한 최소 파일**이기 때문입니다.

- 루트 주소로 접근 → `page.tsx`의 컴포넌트 내용이 `layout.tsx`의 `children` 자리에 렌더링

## 새로운 경로 정의하기: /about

방법은 간단합니다.

```
app/
 └── about/
      └── page.tsx
```

```tsx
// app/about/page.tsx
export default function Page() {
  return <div>About Page</div>;
}
```

- `about` **폴더**: 경로를 구성하는 **세그먼트 폴더**로 인식
- `page.tsx` **파일**: 해당 경로에 접근했을 때 보여지는 **페이지 컴포넌트**로 인식
- `/about` 경로로 접근하면, `about/page.tsx`의 내용이 `layout.tsx`의 `children` 자리에 렌더링됨

## 새로운 경로 정의하기: /blog

```
app/
 └── blog/
      └── page.tsx
```

```tsx
// app/blog/page.tsx
export default function Page() {
  return <div>블로그 페이지</div>;
}
```

- `blog` 폴더가 경로를 구성하는 **첫 번째 세그먼트** 역할
- `/blog` 주소로 접근 시 `blog/page.tsx`의 내용이 `layout.tsx`의 `children` 자리에 렌더링

## page.tsx의 함수 이름

- 모든 `page.tsx`의 함수 이름을 `Page`로 동일하게 지어도 전혀 문제없음
- 다만 가독성을 위해 세그먼트 폴더 이름에 맞춰 이름을 다르게 짓기도 함
  - 예: `about/page.tsx` → `AboutPage`
  - 예: `blog/page.tsx` → `BlogPage`
- 함수 이름은 **전적으로 개발자의 자유로운 선택**

## 정리

| 구성 요소  | 역할                                            |
| ---------- | ----------------------------------------------- |
| 폴더       | 경로를 구성하는 **세그먼트**                    |
| `page.tsx` | 해당 경로에서 보여지는 **페이지 콘텐츠**를 정의 |

- Next.js의 App Router는 이러한 단순한 구조 덕분에 **별도의 라우트 등록 없이 폴더와 파일만으로 손쉽게 라우트를 정의**할 수 있음
- 이것이 App Router의 가장 큰 장점
