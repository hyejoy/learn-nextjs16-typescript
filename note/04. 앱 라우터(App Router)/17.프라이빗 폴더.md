# Private 폴더 (Private Folders)

## 문제 상황

App Router에서는 `app` 폴더 하위에 새로운 폴더를 만들면, 그 폴더는 기본적으로 **라우트 세그먼트**로 인식됩니다.

하지만 실제로는 라우트가 아닌 용도로 `app` 폴더 하위에 폴더를 만들어야 할 때가 있습니다.

- UI 컴포넌트 모음 폴더
- 유틸리티 함수 폴더
- 서비스 로직 폴더

## 예시로 확인하기

```
app/
 ├── components/
 │    └── Button.tsx   (클라이언트 컴포넌트)
 └── page.tsx           (루트 페이지, Button을 import해서 렌더링)
```

- 루트 경로(`/`)에 접근하면 `Button` 컴포넌트가 정상적으로 렌더링됨
- 이때 `components` 폴더에는 `page.tsx`가 없으므로 `/components` 경로로 직접 접근하면 **404 에러**

### 문제: 잠재적인 라우트 세그먼트로 취급됨

```
app/
 └── components/
      └── page.tsx   ← 이걸 추가하면?
```

- `components` 폴더 안에 `page.tsx`만 추가하면, **즉시 `/components` 경로가 실제로 동작하는 라우트가 됨**
- 즉, 개발자의 의도가 "앱 내부에서만 쓰는 컴포넌트 모음 폴더"였다고 해도, Next.js 입장에서는 **언제든 페이지 경로가 될 수 있는 잠재적 라우트 세그먼트 폴더**로 취급함

## 해결책: Private 폴더

폴더 이름 앞에 **언더스코어(`_`)**를 붙이면 **Private 폴더**로 지정됩니다.

```
app/
 └── _components/
      └── Button.tsx
```

### Private 폴더의 특징

- Next.js의 App Router에서 **라우트 세그먼트로 인식되지 않음**
- 오직 **일반 폴더**로만 취급됨
- `/_components`라는 경로로 브라우저에서 접근하려고 해도 **404 에러** 발생 (그 안에 `page.tsx`가 있어도 무관)

## 정리

| 폴더명             | 라우트 세그먼트 여부                                               |
| ------------------ | ------------------------------------------------------------------ |
| `app/components/`  | ⭕ 라우트 세그먼트로 인식 가능 (page.tsx 추가 시 즉시 라우트가 됨) |
| `app/_components/` | ❌ 라우트 세그먼트로 인식되지 않음 (Private 폴더)                  |

- `app` 폴더 하위에 라우팅 목적이 아닌 폴더(컴포넌트, 유틸, 서비스 로직 등)를 만들어야 한다면, **폴더명 앞에 `_`를 붙여 Private 폴더로 지정**하면 됩니다.
- 이렇게 하면 실수로 해당 폴더가 URL 경로로 노출되는 것을 방지할 수 있습니다.
