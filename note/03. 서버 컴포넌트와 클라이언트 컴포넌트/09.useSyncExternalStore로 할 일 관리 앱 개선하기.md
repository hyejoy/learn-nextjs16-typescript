# useSyncExternalStore로 할 일 관리 앱 개선하기

이전 시간에 살펴본 `setStateInEffect` ESLint 경고를 해결하는 방법으로, `useSyncExternalStore` 훅을 활용해 할 일 관리 앱의 구조를 실제로 개선해봅니다.
코드 참고 : git checkout feature/mission03-01

## 1단계: 커스텀 훅으로 로직 분리

먼저 컴포넌트에 흩어져 있던 로직을 정리하기 위해 커스텀 훅으로 옮깁니다.

```
hooks/
 └── useTodoStore.ts
```

```tsx
// hooks/useTodoStore.ts
export function useTodoStore() {
  // 기존 useState, useEffect, uuid 관련 로직을 모두 이곳으로 이동
  // ...
  return { todos, addTodo, updateTodo, toggleTodo, deleteTodo, isLoading };
}
```

컴포넌트에서는 다음과 같이 간단히 사용합니다.

```tsx
const { todos, addTodo, updateTodo, toggleTodo, deleteTodo, isLoading } =
  useTodoStore();
```

⚠️ **주의**: 커스텀 훅으로 분리했다고 해서 근본적인 ESLint 에러가 해결되는 것은 아닙니다. `setTimeout`을 제거해봐도 여전히 `setStateInEffect` 경고가 발생합니다. 구조 자체를 바꿔야 합니다.

## 2단계: useSyncExternalStore의 세 가지 매개변수 구성

```tsx
useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);
```

### ① subscribe

외부 저장소(localStorage)의 값이 바뀌었을 때 React에게 알려주는 함수입니다.

```tsx
const subscribe = (callback: () => void) => {
  window.addEventListener("storage", callback);
  window.addEventListener("todo-storage", callback); // 커스텀 이벤트
  return () => {
    window.removeEventListener("storage", callback);
    window.removeEventListener("todo-storage", callback);
  };
};
```

- 브라우저의 기본 `storage` 이벤트는 **다른 탭**에서 발생한 변경만 감지 가능하고, **자기 자신의 탭**에서 일어난 변경은 감지하지 못함
- 그래서 `todo-storage`라는 **커스텀 이벤트**를 별도로 등록하여 자기 탭의 변경도 감지하도록 처리
- 등록한 이벤트 리스너는 반드시 `removeEventListener`로 정리(cleanup)

### ② getSnapshot

렌더링 시점마다 "지금 값이 뭐야?"라고 조회하는 함수. 클라이언트에서 실행됩니다.

```tsx
const getSnapshot = () => {
  return localStorage.getItem("todos") ?? "[]";
};
```

### ③ getServerSnapshot

서버 렌더링 환경에서 사용할 초깃값. 서버에는 `localStorage`가 없으므로 빈 배열을 문자열로 반환합니다.

```tsx
const getServerSnapshot = () => {
  return "[]";
};
```

## 3단계: useSyncExternalStore 적용

```tsx
const todosRaw = useSyncExternalStore(
  subscribe,
  getSnapshot,
  getServerSnapshot,
);
```

- 기존에 `useState`로 관리하던 `todos` 상태는 제거
- `todosRaw`는 문자열(JSON) 형태이므로 파싱이 필요

```tsx
const todos: Todo[] = useMemo(() => JSON.parse(todosRaw), [todosRaw]);
```

- 컴포넌트가 리렌더링될 때마다 매번 파싱하지 않도록 `useMemo`로 **수동 메모이제이션** 적용

## 4단계: 로컬 스토리지 저장 헬퍼 함수 + 커스텀 이벤트 발행

```tsx
const setStorage = (nextTodos: Todo[]) => {
  localStorage.setItem("todos", JSON.stringify(nextTodos));
  window.dispatchEvent(new Event("todo-storage"));
};
```

- `setItem`으로 로컬 스토리지에 저장
- `dispatchEvent`로 `todo-storage` 커스텀 이벤트를 **강제로 발생**시켜, `subscribe`에 등록된 콜백이 실행되도록 트리거
- 이 트리거가 있어야 `useSyncExternalStore`가 값이 바뀌었음을 인지하고 `getSnapshot`을 다시 호출

## 5단계: 기존 로직을 setStorage 기반으로 변경

기존에 `setTodos((prev) => ...)` 형태의 **콜백 함수 업데이트 패턴**은 사용할 수 없습니다. `todosRaw`/`todos`는 상태 업데이트 함수가 아니라 매번 조회되는 스냅샷 값이기 때문입니다.

```tsx
// Before
setTodos((prev) => [...prev, newTodo]);

// After
setStorage([...todos, newTodo]);
```

- 콜백 함수 대신 **현재 `todos` 값을 직접 참조**하여 새 배열을 만들고 `setStorage`에 전달
- 타입은 `Todo[]`로 명시하여 타입 에러 방지
- 관련된 `useEffect`는 더 이상 필요 없으므로 제거

## 6단계: 결과 확인

- 새로고침 시 로컬 스토리지의 값이 정상적으로 복구됨
- 한 탭에서 할 일을 추가하면 **다른 탭에서도 자동으로 동기화**됨
  - `subscribe`의 구독 상태 변경 → `useSyncExternalStore` 재실행 → `todosRaw` 갱신 → 새로운 `todos` 파싱

## 7단계: 남은 문제 — 새로고침 시 깜빡임 (Hydration 불일치)

### 원인

- `useSyncExternalStore`는 **서버 스냅샷**과 **클라이언트 스냅샷**이 다름
  - 서버: `getServerSnapshot()` → 빈 배열
  - 클라이언트: 하이드레이션 완료 후 `getSnapshot()` → 로컬 스토리지의 실제 데이터
- 따라서 처음에는 빈 배열로 렌더링되었다가, 하이드레이션이 끝나면 실제 데이터로 바뀌면서 **깜빡임 현상** 발생

### 잘못된 해결 시도

```tsx
const [isLoading, setIsLoading] = useState(false);

useEffect(() => {
  setIsLoading(true); // ❌ 여전히 setStateInEffect 경고 발생
}, []);
```

- `useEffect` 내부에서 동기적으로 `setState`를 호출하는 패턴이라 동일한 ESLint 경고가 다시 발생

### 올바른 해결책: useIsMounted 커스텀 훅

```tsx
// hooks/useIsMounted.ts
import { useSyncExternalStore } from "react";

export function useIsMounted() {
  return useSyncExternalStore(
    () => () => {}, // subscribe: 구독할 필요 없음 (빈 함수)
    () => true, // getSnapshot: 클라이언트에서는 true
    () => false, // getServerSnapshot: 서버에서는 false
  );
}
```

- 서버에서는 `false`, 클라이언트 하이드레이션 이후에는 `true`를 반환
- `useSyncExternalStore`의 동작 원리(서버/클라이언트 스냅샷이 다르면 하이드레이션 후 재조정)를 활용해 **마운트 여부를 안전하게 감지**

### 적용

```tsx
const mounted = useIsMounted();

return mounted ? <TodoList todos={todos} ... /> : null;
```

- `mounted`가 `true`일 때만 실제 목록을 렌더링 → 깜빡임 현상 해결

## 정리

| 문제                                                                        | 해결 방법                                                                 |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `useEffect` 내부에서 로컬 스토리지 상태를 `setState`로 동기화 → ESLint 경고 | `useSyncExternalStore`로 외부 상태를 직접 구독                            |
| 자기 자신 탭의 변경사항이 감지되지 않음                                     | 커스텀 이벤트(`todo-storage`)를 등록하고 `dispatchEvent`로 강제 발생      |
| 서버/클라이언트 스냅샷 불일치로 인한 하이드레이션 깜빡임                    | `useIsMounted` 커스텀 훅으로 마운트 여부를 안전하게 판별 후 조건부 렌더링 |

이 과정을 통해 `setState in useEffect` 이슈를 해결하는 동시에, `localStorage`처럼 React 외부에 있는 상태를 더 안전하고 일관되게 동기화하는 구조로 앱을 개선했습니다.
