# Next.js 레이아웃 시스템과 children props

앞서 배운 `children` props를 통한 서버/클라이언트 조합 원리는 사실 Next.js의 **레이아웃 시스템**에 이미 기본으로 적용되어 있던 개념입니다.

## layout.tsx의 children

`layout.tsx`를 열어보면 `children` props를 렌더링하는 코드가 있습니다.

```tsx
export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html>
      <body>{children}</body>
    </html>
  );
}
```

즉, 브라우저에서 최종적으로 보이는 화면은 **`page.tsx`의 컴포넌트가 `layout.tsx`의 `children` 자리에 렌더링되어 표시된 형태**입니다.

## 합성 구조

Next.js는 내부적으로 `layout.tsx`와 `page.tsx`를 하나의 React 트리로 합성할 때:

- **레이아웃 = 부모**
- **페이지 = 자식**

으로 배치합니다. 이때 이 `children` 구조가 바로 **서버/클라이언트 실행 컨텍스트를 구분하는 기준**이 됩니다.

## 루트 레이아웃이 클라이언트 컴포넌트인 경우

루트 레이아웃에 `"use client"`를 붙여 클라이언트 컴포넌트로 바꿔도, 그 하위의 `page.tsx`가 `async`가 붙은 서버 전용 코드(예: 메타데이터 처리)를 포함하고 있어도 **에러가 발생하지 않습니다.**

### 이유

- 페이지 컴포넌트는 레이아웃의 `children`으로 전달될 때 **이미 서버에서 렌더링이 완료된 결과물**로 전달됨
- 클라이언트 레이아웃이 페이지 컴포넌트(서버 컴포넌트)를 **직접 실행하는 것이 아니라**, 서버에서 실행 완료된 렌더링 결과만 `children` props로 받아 표시만 함
- 따라서 실행 컨텍스트가 다르므로 문제없이 동작

### 구조 (그림 개념)

```
컴포넌트 트리 (수직 관계)        실행 컨텍스트 (독립)
RootLayout (클라이언트)          RootLayout ─┐ (독립)
 └─ children: Page (서버)        Page ───────┘ (독립)
```

- 겉보기엔 레이아웃과 페이지가 부모-자식의 수직 관계
- 하지만 **실행 컨텍스트는 서로 독립**
- 따라서 **RootLayout → Page로 props 전달 불가능**

## 루트 레이아웃이 서버 컴포넌트인 경우

결과는 동일합니다. 페이지 컴포넌트는 이미 서버에서 실행되어 렌더링된 결과가 `children` props로 전달되어 표시만 되는 구조이므로, **루트 레이아웃이 서버든 클라이언트든 상관없이 페이지 컴포넌트는 독립적으로 동작**합니다.

## 헤더 / 푸터 컴포넌트를 추가하면?

루트 레이아웃에 `Header`, `Footer` 컴포넌트를 **직접 import하여 렌더링**한다고 가정하면:

```
RootLayout
 ├─ import & render Header   ─┐
 ├─ import & render Footer   ─┤ 같은 실행 컨텍스트
 └─ children: Page (서버)    ─┘ 독립된 실행 컨텍스트
```

| 관계                | props 전달 가능 여부                   |
| ------------------- | -------------------------------------- |
| RootLayout → Header | ✅ 가능 (직접 import & render)         |
| RootLayout → Footer | ✅ 가능 (직접 import & render)         |
| RootLayout → Page   | ❌ 불가능 (children으로 전달받는 관계) |

`Header`, `Footer`는 레이아웃이 직접 import하여 렌더링하므로 같은 실행 컨텍스트를 공유해 props 전달이 가능하지만, `Page`는 여전히 서버에서 렌더링 완료된 결과만 전달받는 것이므로 실행 컨텍스트가 다르고 props 전달이 불가능합니다.

## 정리

- Next.js의 레이아웃 시스템은 **`children` props를 기반으로 서버와 클라이언트의 경계를 안전하게 분리**
- 레이아웃이 서버 컴포넌트든 클라이언트 컴포넌트든, **페이지 컴포넌트는 항상 자신만의 독립된 실행 컨텍스트를 가진 서버 컴포넌트**로 동작 가능
- 이 구조를 이해하면:
  - Next.js의 렌더링 원리
  - 레이아웃과 페이지 컴포넌트 사이에서 props 전달이 불가능한 이유

를 자연스럽게 이해할 수 있음
