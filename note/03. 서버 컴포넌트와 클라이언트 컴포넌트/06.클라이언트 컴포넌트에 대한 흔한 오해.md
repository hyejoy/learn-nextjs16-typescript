# 클라이언트 컴포넌트에 대한 흔한 오해

## 흔한 오해

> "클라이언트 컴포넌트는 서버에서 실행되지 않고 클라이언트에서만 실행된다"

**틀린 생각입니다.**

| 구분                | 사실                                                                         |
| ------------------- | ---------------------------------------------------------------------------- |
| 서버 컴포넌트       | 서버에서만 실행 ✅                                                           |
| 클라이언트 컴포넌트 | 클라이언트에서 실행되는 것은 맞지만, **클라이언트에서만 실행되는 것은 아님** |

## 코드로 확인하기

### 1. 서버 컴포넌트에서 console.log

```tsx
// page.tsx (서버 컴포넌트)
console.log("Hello World");
```

- 저장 후 확인하면 **터미널**에 `Hello World` 출력
- 터미널에 출력되었다는 것은 **서버에서 실행**되었다는 의미
- 최신 Next.js에서는 **브라우저 콘솔에서도** 서버 컴포넌트의 로그를 확인 가능
  - 이때 메시지 앞에 **"서버"** 배지(badge)가 표시됨
- 결론: **서버 컴포넌트의 console.log는 서버에서만 실행됨**

### 2. 페이지 컴포넌트를 클라이언트 컴포넌트로 변경 후 확인

```tsx
"use client";
console.log("Hello World");
```

결과:

- **터미널**에도 `Hello World` 출력됨
- **브라우저 콘솔**에도 `Hello World` 출력됨
- 단, 이번에는 콘솔 메시지 앞에 **"서버" 배지가 없음**

### 의미

- 콘솔이 **서버에서도, 클라이언트에서도** 모두 실행되었다는 뜻
- Next.js는 **초기 HTML을 생성하기 위해** 서버에서 서버 컴포넌트뿐 아니라 **클라이언트 컴포넌트의 코드도 함께 실행**함
- 즉, **클라이언트 컴포넌트 코드는 클라이언트에서만 실행되는 것이 아님**

이 사실은 향후 학습에서 매우 중요합니다.

## 실전 예시: Hydration Error

랜덤 숫자를 렌더링하는 클라이언트 컴포넌트를 작성해봅니다.

```tsx
"use client";

// eslint-disable-next-line
const randomNumber = Math.floor(Math.random() * 10) + 1;

console.log(randomNumber);

export default function Page() {
  return <div>{randomNumber}</div>;
}
```

새로고침해보면 랜덤 숫자는 화면에 잘 출력되지만, **콘솔에 긴 에러 메시지**가 발생합니다.

### Hydration Failed 에러

- **서버가 생성한 HTML**과 **클라이언트가 Hydration하며 생성한 결과**가 서로 달라서 발생하는 에러
- 쉽게 말하면: **서버에서 렌더링된 HTML 구조**와 **클라이언트에서 렌더링된 HTML 구조**가 다르기 때문에 발생

### 왜 발생했는가

- 클라이언트 컴포넌트 코드가 **서버에서도 한 번 실행**되고, **클라이언트에서도 다시 실행**됨
- `Math.random()`은 실행할 때마다 값이 달라지므로:
  - 서버 실행 시: 예) `9`
  - 클라이언트 실행 시: 예) `7`, `8`, `6`, `8`... (매번 다름)
- 서버 렌더링 결과와 클라이언트 렌더링 결과가 일치하지 않아 **Hydration 에러 발생**

## 정리

- 클라이언트 컴포넌트는 **클라이언트에서 실행되는 것은 맞지만, 클라이언트에서만 실행되는 것은 아님**
- Next.js는 초기 HTML 생성을 위해 클라이언트 컴포넌트도 **서버에서 먼저 한 번 실행**함
- 이 원리를 이해해야 `Math.random()`, `Date.now()`처럼 **실행할 때마다 값이 달라지는 코드**로 인한 **Hydration 관련 에러를 피할 수 있음**

> Hydration의 정확한 개념은 추후 학습에서 더 자세히 다룰 예정입니다.
