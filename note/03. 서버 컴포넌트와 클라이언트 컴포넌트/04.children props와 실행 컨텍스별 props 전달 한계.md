# children props와 실행 컨텍스트별 props 전달 한계

이전 시간에 배운 `children` props를 통한 서버 컴포넌트 표시 방법을, 코드로 직접 확인하고 한 단계 더 확장해봅니다.

## 기본 구조 복습

```
Page (서버)
 ├─ import & render ClientWrapper (클라이언트) ─ children으로 DataFetch 전달
 └─ import & render DataFetch (서버)
```

- **Page → ClientWrapper**: props 전달 ✅ 가능
- **Page → DataFetch**: props 전달 ✅ 가능
- **ClientWrapper → DataFetch**: props 전달 ❌ 불가능 (children으로 렌더링되는 자리에는 React 문법상 props를 넣을 방법이 없음)

### 코드로 검증

**Page → ClientWrapper**

```tsx
<ClientWrapper name="client">
  <DataFetch />
</ClientWrapper>
```

```tsx
// ClientWrapper.tsx
export default function ClientWrapper({
  name,
  children,
}: Readonly<{ name: string; children: React.ReactNode }>) {
  return (
    <div>
      <h1>{name}</h1>
      {children}
    </div>
  );
}
```

→ 정상 동작 (props 전달 가능)

**Page → DataFetch**

```tsx
<DataFetch name="patch" />
```

```tsx
// DataFetch.tsx
export default async function DataFetch({ name }: { name: string }) {
  return <div>{name}</div>;
}
```

→ 정상 동작 (props 전달 가능)

**ClientWrapper → DataFetch**
→ children 자리에는 props를 주입할 방법이 없으므로 불가능

## 구조 확장: 서버 → 클라이언트 → 서버

이제 `DataFetch`(서버) 하위에 `UserPatch`(서버) → `UserForm`(클라이언트)을 연쇄로 연결합니다.

```
Page (서버)
 └─ ClientWrapper (클라이언트)
      └─ children: DataFetch (서버)
            └─ UserPatch (서버)
                  └─ UserForm (클라이언트)
```

컴포넌트 트리는 수직으로 이어지지만, **실행 컨텍스트는 import/render 관계 단위로 분리**됩니다.

### props 전달 가능 여부

| 관계                      | 가능 여부 | 이유                             |
| ------------------------- | --------- | -------------------------------- |
| ClientWrapper → DataFetch | ❌        | children으로 전달받는 관계       |
| DataFetch → UserPatch     | ✅        | DataFetch가 직접 import & render |
| UserPatch → UserForm      | ✅        | UserPatch가 직접 import & render |

```tsx
// DataFetch.tsx
<UserPatch name="UserPatch" />
```

```tsx
// UserPatch.tsx
export default async function UserPatch({ name }: { name: string }) {
  return <UserForm name={name} />;
}
```

```tsx
// UserForm.tsx
"use client";
export default function UserForm({ name }: { name: string }) {
  return <div>{name}</div>;
}
```

→ 모두 정상적으로 props 전달됨

## 한 단계 더: UserForm도 children을 받는 구조로 변경

`UserForm`(클라이언트)을 `ClientWrapper`처럼 `children`을 렌더링하는 방식으로 바꾸고, `UserPatch`(서버)에서 새로운 서버 컴포넌트 `PostPatch`를 import하여 `UserForm`의 children으로 전달합니다.

```
UserPatch (서버)
 └─ UserForm (클라이언트)
      └─ children: PostPatch (서버)
```

```tsx
// UserForm.tsx
"use client";
export default function UserForm({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return <div>{children}</div>;
}
```

```tsx
// UserPatch.tsx
<UserForm>
  <PostPatch />
</UserForm>
```

이 구조에서 **또 하나의 실행 컨텍스트 경계**가 생깁니다.

| 관계                  | 가능 여부                                  |
| --------------------- | ------------------------------------------ |
| UserForm → PostPatch  | ❌ 불가능 (children 관계)                  |
| UserPatch → PostPatch | ✅ 가능 (UserPatch가 직접 import & render) |

```tsx
// UserPatch.tsx
<PostPatch name="postPatch" />
```

```tsx
// PostPatch.tsx
export default async function PostPatch({ name }: { name: string }) {
  return <div>{name}</div>;
}
```

→ 정상적으로 props 전달됨

## 정리

- `children` props를 사용한 렌더링 구조는 **서버 → 클라이언트 → 서버**로 컴포넌트를 계속 이어갈 수 있게 해줌
- 하지만 그 과정에서 **서로 다른 실행 컨텍스트(execution context)**가 개입되므로, props 전달에는 명확한 한계가 존재함
- **핵심 규칙**: props 전달이 가능한 관계는 언제나 "누가 직접 import하여 렌더링하는가"로 결정됨
  - import & render하는 컴포넌트 → 그 대상 컴포넌트: props 전달 가능
  - children으로 결과만 전달받는 관계: props 전달 불가능
- 트리 구조상으로는 수직으로 연결되어 보여도, 실행 컨텍스트 단위로 나누어 생각해야 props 흐름을 정확히 이해할 수 있음

이 개념은 헷갈리기 쉬우므로 여러 번 반복 학습이 필요합니다.
