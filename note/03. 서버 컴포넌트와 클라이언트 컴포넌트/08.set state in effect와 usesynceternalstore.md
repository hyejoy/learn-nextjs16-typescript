# set-state-in-effect와 useSyncExternalStore

## set-state-in-effect ESLint 경고

할 일 관리 앱 미션을 진행하며 마주친 `set-state-in-effect` 규칙에 의한 ESLint 경고를 다룹니다.

### 규칙 내용

> `useEffect` 내부에서 **동기적으로 상태 업데이트 함수(setState)를 호출**하면 연쇄적인 렌더링이 발생할 수 있다는 경고

즉, `useEffect` 안에서 바로 `setState`를 호출하는 패턴은 문제가 될 가능성이 있으니 가급적 피하라는 의미입니다.

### 현재 시점의 사실

- 아직 이 코드 패턴이 **심각한 성능 저하나 버그를 유발한다는 사례가 명확히 보고된 것은 아님**
- 오히려 지금까지의 패턴은 React에서 **오랫동안 정석처럼 사용되어온 코드 스타일**
- 따라서 ESLint 경고는 발생하지만, 당장 기능적으로 문제가 생기는 것은 아님

### 그런데 왜 이런 경고가 생겼을까?

이 질문에 답하려면 **React 컴파일러**를 이해해야 합니다.

## React 컴파일러

- 2025년 10월, React팀이 수년간 개발해온 **React 컴파일러가 정식 릴리즈**
- `useMemo`, `useCallback`, `React.memo`를 수동으로 사용하지 않아도 **자동으로 메모이제이션을 적용**해주는 **빌드 타임 도구**
- Next.js도 React 기반 프레임워크이므로, 최신 Next.js 환경은 이미 **React 컴파일러가 적극 적용된 상태**로 동작

### 문제점

- React 컴파일러가 자동 메모이제이션을 **안전하게** 적용하려면, React팀이 공식 권장하는 **코드 규칙을 지켜서 작성된 코드**여야 함
- 이 규칙을 강제하고 실수를 방지하는 역할을 하는 것이 바로 **ESLint 규칙들**
- 따라서 `set-state-in-effect` 경고를 무시하거나 우회하는 것은 **React가 의도한 컴파일러 최적화 흐름과 어긋나는 선택**이 될 수 있음

## localStorage 사용의 추가 문제

기존 할 일 관리 앱은 `localStorage`를 사용하고 있는데, 다음과 같은 구조적 문제가 있습니다.

- **다른 브라우저 탭에서 발생한 변경 사항이 자동으로 동기화되지 않음**
- 즉, `set-state-in-effect` 경고와 별개로 **구조적으로 개선이 필요한 코드**

## 해결책: useSyncExternalStore

### 개념

- **React 18**에서 도입된 공식 훅
- **React 외부에 존재하는 상태**를 React 내부 상태처럼 **안전하고 일관되게 구독**할 수 있도록 설계됨

### React 외부 상태란?

`useState`, `useReducer`로 관리되지 않는 모든 데이터:

- 브라우저 API
- 전역 변수
- 로컬 스토리지 / 세션 스토리지
- Redux, Zustand 같은 외부 상태 관리 라이브러리의 상태

→ 할 일 관리 앱은 `localStorage`를 직접 다루고 있으므로 `useSyncExternalStore`를 적용하기에 매우 적합한 사례

### 세 가지 매개변수

```tsx
useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);

const state = useSyncExternalStore(
  subscribe, // 스토어가 변경될 때 실행할 구독 함수
  getSnapshot, // 현재 스토어 값을 반환하는 함수
  getServerSnapshot, // (선택) 서버 렌더링 시 사용할 갓 반환 함수
);
```

| 매개변수            | 역할                                                                                                                       |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `subscribe`         | React에게 "이 데이터가 바뀌면 이 콜백을 실행해줘"라고 등록                                                                 |
| `getSnapshot`       | React가 렌더링할 때마다 "지금 이 데이터의 값은 뭐야?"라고 조회. 반환 값이 이전과 다르면 리렌더링 발생                      |
| `getServerSnapshot` | 서버 렌더링 환경에서 사용할 초깃값 반환. 일반 SPA에서는 불필요하지만, Next.js처럼 서버에서 HTML을 생성하는 환경에서는 중요 |

## 다음 학습

`useSyncExternalStore` 훅을 실제로 적용해서 기존 할 일 관리 앱(localStorage 기반)을 개선하는 과정을 다음 영상에서 다룰 예정입니다. 실제 코드를 통해 적용해보면 이 훅이 왜 필요한지 더 명확하게 이해할 수 있습니다.
