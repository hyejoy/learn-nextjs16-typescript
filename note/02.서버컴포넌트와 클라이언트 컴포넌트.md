# 서버 컴포넌트와 클라이언트 컴포넌트

React 19에서 서버 컴포넌트(Server Components)가 공식 안정화 버전으로 출시되었고,
Next.js는 이를 공식적으로 도입하여 서버 컴포넌트와 클라이언트 컴포넌트를 함께 사용하는 프레임워크입니다.

## 서버 컴포넌트 (Server Component)

- 이름 그대로 **서버에서 코드 실행**
- 브라우저에서 실행되는 자바스크립트의 양이 줄어들어 클라이언트 부담 감소

### 장점

- **보안성**: 코드 실행 과정이 외부(브라우저)로 노출되지 않음 → 내부 로직이 보이지 않아 안전
- **효율성**: 브라우저에서 실행할 JS 양 감소

### 적합한 용도

- 데이터베이스 조회
- 외부 API 호출
- API 키, 토큰 등 비공개 정보가 필요한 처리

### 한계

- 브라우저 전용 기능 사용 불가
  - 이벤트 핸들러 (`onClick` 등)
  - 브라우저 전용 API

## 클라이언트 컴포넌트 (Client Component)

- 이름 그대로 **클라이언트(브라우저)에서 코드 실행**
- 보안적으로는 서버 컴포넌트보다 안전하지 않음
- 브라우저 전용 기능 사용 가능
  - 이벤트 핸들러
  - 브라우저 전용 API

## Next.js에서의 역할 분담

| 구분                | 담당 작업                                               |
| ------------------- | ------------------------------------------------------- |
| 서버 컴포넌트       | DB 쿼리, API 호출, 비밀키 처리 등                       |
| 클라이언트 컴포넌트 | 사용자 입력, 이벤트 처리, 브라우저 전용 API 등 상호작용 |

### 기본값

- **Next.js의 기본값은 서버 컴포넌트**
- 별도 설정이 없으면 모든 컴포넌트는 자동으로 서버 컴포넌트로 동작
- 클라이언트 컴포넌트로 지정하려면 컴포넌트 상단에 지시문 추가

```tsx
"use client";
```

## 컴포넌트 트리 구조 규칙

> **서버 컴포넌트는 클라이언트 컴포넌트의 하위에 올 수 없다**

### 이유

- 클라이언트 컴포넌트는 브라우저에서 **리렌더링 가능**
- 서버 컴포넌트는 **서버에서만 실행** 가능 (브라우저에서 재실행 불가)
- 클라이언트 컴포넌트가 리렌더링될 때, 그 하위에 있는 서버 컴포넌트도 함께 리렌더링되어야 한다면 이는 구조적으로 불가능
- 이미 서버에서 렌더링되어 전달된 결과물은 브라우저에서 다시 실행될 수 없음

따라서 컴포넌트 트리는 항상 다음 방향으로만 구성됩니다.

```
서버 컴포넌트 → 클라이언트 컴포넌트
```

이 순서를 거꾸로 뒤집는 것은 React의 렌더링 원리에 어긋납니다.

## 정리

| 구분                | 적합한 용도                |
| ------------------- | -------------------------- |
| 서버 컴포넌트       | 보안이 필요한 데이터 처리  |
| 클라이언트 컴포넌트 | 사용자 인터랙션, 상태 관리 |

서버와 클라이언트의 역할을 분리함으로써 React와 Next.js는 **성능**, **보안**, **개발 효율성**을 모두 향상시켰습니다.

## 다음 학습 방향

직접 코드를 작성하며 서버 컴포넌트와 클라이언트 컴포넌트가 실제로 어떻게 구분되고 함께 동작하는지 살펴볼 예정입니다.
